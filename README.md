# Ultimate Chess App — Telegram Mini App

Шахматы внутри Telegram: анимированная доска, SVG-фигуры (Neo / Классика), темы Telegram,
MainButton / BackButton, вибро-отклик, звуки, Stockfish (1–5) и Pass & Play.

## Структура

```
ultimate-chess/
├── index.html          # SDK Telegram + экраны (меню / настройки / игра / турниры / админ)
├── css/style.css       # темы Telegram (CSS-переменные) + web3 glassmorphism
├── server/index.js     # WebSocket-сервер: комнаты, авторизация initData, турниры, выплаты
├── server/.env.example # шаблон секретов (TG_BOT_TOKEN, ADMIN_ID, SSL_CERT/SSL_KEY) — скопируйте в .env
├── server/tournaments.json  # JSON-хранилище турниров и заявок (создаётся автоматически)
└── js/
    ├── main.js         # контроллер: экраны, партии, настройки, онлайн, турниры, админ
    ├── board.js        # доска с анимацией фигур (CSS transform transitions)
    ├── pieces.js       # собственный SVG-спрайт фигур (Neo)
    ├── engine.js       # Stockfish.js в Web Worker (UCI)
    ├── net.js          # WebSocket-клиент комнат
    ├── config.js       # URL WS-сервера и ссылка бота для инвайтов
    ├── sound.js        # звуки ходов на WebAudio (без ассетов)
    └── tg.js           # мост Telegram: тема, MainButton/BackButton, haptics, профиль
```

## Локальный запуск

Нужен любой статический сервер (ES-модули не работают с `file://`):

```bash
python -m http.server 8099
# открыть http://localhost:8099/ultimate-chess/
```

В обычном браузере приложение полностью играбельно: вместо нативных MainButton/BackButton
работают внутриэппные кнопки («Начать игру», «‹»). Тема берётся светлая по умолчанию.

## Онлайн-режим (Multiplayer)

Сервер комнат написан на чистом Node (без npm-зависимостей, свой RFC6455-фрейминг):

```bash
cd server
node index.js            # PORT по умолчанию 8787
```

- Клиент берёт адрес из `js/config.js` (`wsUrl`); перекрыть можно через `?ws=wss://...`
  или `localStorage['uca-ws']` без пересборки.
- Для продакшена задеплойте `server/` на любой хостинг с WebSocket и TLS
  (Render / Fly.io / Railway / VPS) и укажите `wss://`-адрес.
- Кнопка **«Играть онлайн»**: подбор соперника (очередь) или **«Пригласить друга»** —
  создаётся комната, ссылка вида `https://t.me/<bot>/<app>?startapp=ROOM`.
- Приглашённый открывает ссылку: `initDataUnsafe.start_param` (или `?room=` в браузере)
  автоматически подключает его в комнату минуя меню; хост играет белыми.
- Ходы синхронизируются по WebSocket; доска блокируется, когда ход не ваш.
  Обрыв соперника / сдача / потеря связи обрабатываются отдельными оверлеями.

## Турниры с призовым фондом 🏆

Кнопка **«Турниры»** открывает список турниров с плашкой **«Приз: N ₽»**, турнирной сеткой
(bracket) и регистрацией. Победители ТОП-3 получают окно **«Заявка на Приз»** для ввода
реквизитов (карта / СБП / кошелёк); после отправки кнопка меняется на
**«Заявка отправлена, ожидайте выплаты»**.

### Запуск сервера с турнирами

Скопируйте шаблон и впишите свой токен (файл `.env` читается сервером сам, без зависимостей;
реальные переменные окружения имеют приоритет над ним):

```bash
cd server
cp .env.example .env      # затем вписать TG_BOT_TOKEN=123456:ABC...
node index.js
```

Либо без `.env`, через окружение:

```bash
cd server
TG_BOT_TOKEN=123456:ABC... ADMIN_ID=ваш_telegram_id node index.js
```

> `.env` содержит секрет — **не коммитьте его**. В репозитории лежит только `.env.example`.

- `TG_BOT_TOKEN` — токен бота от @BotFather. **Обязателен в продакшене**: по нему сервер
  проверяет подпись Telegram `initData` (HMAC-SHA256) и сам определяет `user.id`.
  Без токена сервер работает в **DEV-режиме** и доверяет идентичности клиента
  (`?as=<id>@<username>`) — только для локального тестирования в браузере.
- `ADMIN_ID` — Telegram-ID владельца, **уже прописан**: `498258870`
  (`const ADMIN_ID` в `js/main.js` и `ADMIN_ID_CONST` в `server/index.js` — значения должны
  совпадать). Права проверяются **на сервере** по подписанному `initData`, поэтому
  подменить ID через devtools нельзя: клиент лишь рисует кнопку, а каждое действие
  админа сервер сверяет заново. Env-переменная `ADMIN_ID` перекрывает константу.
  Кнопка «Панель организатора» в главном меню создаётся в DOM **только** для владельца —
  у остальных её нет в дереве элементов вовсе (не просто скрыта).
- `DATA_FILE` — путь JSON-хранилища (по умолчанию рядом с `index.js`; если папка защищена,
  например Windows Controlled Folder Access, сервер автоматически пишет в temp).
- `SSL_CERT` + `SSL_KEY` — пути к PEM-файлам для **прямого TLS** на самом Node-сервере
  (тогда клиент подключается по `wss://host:PORT` без обратного прокси). Если TLS
  терминируется обратным прокси (Nginx / Caddy / Cloudflare / Render), эти переменные
  не нужны — оставьте сервер на `ws://` и укажите в `js/config.js` адрес `wss://`.
- `SCHEDULE_SWEEP_MS` — как часто сервер проверяет расписание турниров (по умолчанию 5000).
- `HEARTBEAT_MS` — интервал ping/pong, по которому отсеиваются «полумёртвые» соединения
  (по умолчанию 25000); без него оборвавшийся телефон может удерживать место в комнате.

### Почему на телефоне «не видно турниров»

Список турниров пуст не из-за вёрстки, а потому что телефон не смог подключиться к серверу:

- `ws://localhost:8787` на телефоне — это **сам телефон**, сервера там нет;
- Telegram открывает Mini App по **https**, а браузер блокирует незащищённый `ws://`
  внутри https-страницы (mixed content) — нужен **`wss://`**;
- сервер должен быть задеплоен и доступен из интернета (Render / Fly.io / Railway / VPS).

Чтобы не гадать, экран «Турниры» показывает состояние соединения: **«⏳ Подключение…»**,
а при неудаче — панель с текущим адресом сервера и подсказкой. Адрес можно перекрыть без
пересборки: `?ws=wss://ваш-домен` в ссылке на Mini App или `localStorage['uca-ws']`.
Пока соединения нет, надпись «Пока нет активных турниров» скрывается — она не должна
выглядеть как «турниров нет».

Вёрстка адаптирована под маленькие экраны Telegram: на высотах ≤ 720px и ≤ 600px меню
уплотняется, чтобы кнопки **«Турниры»** и **«Настройки»** не уезжали ниже первого экрана,
на ширине ≤ 380px уменьшаются карточки турниров и сетка.


### Админ-панель (🛡️, видна только владельцу)

- Форма создания: **Название**, **Количество мест** (3/4/8/16/32), **Призовой фонд (в рублях)**,
  **Время начала (необязательно)** → **«Создать турнир»**.
- Время начала задаётся полем `datetime-local` или пресетами **«через 10 мин» / «через час» /
  «завтра» / «без расписания»**. Пустое поле = старт вручную.
- Список турниров на регистрации показывает состав, фонд и расписание; кнопка **⏰** применяет
  к турниру время из поля «Время начала» (пустое поле — снимает расписание),
  **«Начать»** — запускает сетку немедленно (нужно ≥ 2 игроков), **✕** — удаляет турнир.
- Раздел **«Выплаты призов 💰»**: таблица заявок ТОП-3 (турнир, место, @username, реквизиты)
  с кнопкой **«Выплачено»**, которая архивирует заявку.

### Расписание старта

- Турнир с `startsAt` стартует **сам**: сервер раз в `SCHEDULE_SWEEP_MS` (по умолчанию 5 с)
  проверяет время и при ≥ 2 зарегистрировавшихся строит сетку и рассылает `match-start`.
- Если время вышло, а игроков меньше двух, старт откладывается: турнир остаётся на регистрации
  с пометкой **«Время прошло, ждём ещё игроков»**, а админ получает `schedule-missed`
  (в приложении — всплывающее сообщение). Как только набирается пара, сетка создаётся сразу.
- Время можно менять и после создания (`tour-set-time`, только на регистрации): поддерживаются
  миллисекунды, секунды и строки вида `2026-09-25T18:30` (трактуются как локальное время сервера);
  дата дальше года вперёд и мусор отклоняются. Расписание переживает перезапуск (лежит в `DATA_FILE`).
- Игрок, который зарегистрировался и закрыл приложение, **не теряет матч**: при следующем входе
  сервер повторно шлёт ему `match-start` той же комнаты и с тем же цветом (цвета матча хранятся
  в `DATA_FILE`, поэтому возобновление работает и после перезапуска сервера).

### Логика матчей

- Сетка single-elimination с байями (BYE) при неполном составе и матчем за 3-е место.
- Мест может быть **3, 4, 8, 16 или 32**. Размер сетки всегда степень двойки: при 3 местах
  сетка строится на 4 слота, третий игрок проходит в финал технической победой, а проигравший
  в полуфинале получает 3-е место. Если зарегистрировалось только двое, сетка сжимается до
  одного финала — «фантомное» 3-е место и лишняя выплата не создаются.
- Призовых мест всегда три: 50% / 30% / 20% фонда (кнопка «Мест» задаёт число **игроков**,
  а не число призовых мест).
- Сервер сам создаёт комнату на каждый матч, назначает цвета и шлёт игрокам `match-start`
  (уведомление о старте тура) — приложение автоматически открывает партию.
- Результат партии клиент отправляет с `matchId`, поэтому игрок может участвовать в двух
  турнирах одновременно: сервер не перепутает, к какому матчу относится счёт.
- Победитель продвигается вверх по сетке; ничья → автоматическая переигровка.
- После финала и матча за 3-е место фиксируются три призёра (50% / 30% / 20% фонда)
  и им открывается форма ввода реквизитов.

### Безопасность и соответствие (важно)

- **`server/.env` — секрет.** Файл добавлен в `.gitignore`; никогда не коммитьте его и не
  выкладывайте в публичный репозиторий. Токен бота даёт полный контроль над ботом: при утечке
  отзовите его в @BotFather (`/revoke`) и впишите новый.
- **Только `wss://` (TLS) в продакшене** — `initData` и реквизиты не должны идти открытым текстом.
  Два варианта: терминировать TLS обратным прокси (Nginx/Caddy/Cloudflare/Render) **или**
  задать `SSL_CERT`+`SSL_KEY` в `server/.env` и слушать `wss://` прямо из Node.
  При запуске сервер печатает, включён ли TLS и DEV/PROD-режим — проверяйте этот лог.
- Реквизиты (карта/СБП/кошелёк) — персональные и платёжные данные: они хранятся минимально
  и **удаляются сразу после отметки «Выплачено»**. Ограничьте доступ к `DATA_FILE`/бэкапам.
- Сбор и обработка платёжных реквизитов и персональных данных подпадает под **152-ФЗ** и,
  при работе с картами, требования **PCI-DSS**. Для реальных выплат используйте
  платёжного агента/юрлицо, согласие на обработку ПДн и не храните полные номера карт.
- Призовой фонд и выплаты организует владелец; приложение лишь собирает и передаёт заявки.

## Деплой и тест в Telegram

1. **Хостинг с HTTPS** (обязательно): GitHub Pages, Netlify, Vercel или Cloudflare Pages.
   Загрузите в корень сайта **только фронтенд**: `index.html`, `css/`, `js/`.
   Папку `server/` (и особенно `server/.env` с токеном) на статический хостинг
   выкладывать **нельзя** — это отдельный Node-хостинг.
   Пример URL: `https://<user>.github.io/<repo>/`.
2. **Создание бота**: в [@BotFather](https://t.me/BotFather) → `/newbot`, получите токен.
3. **Привязка Mini App** (один из способов):
   - `/newapp` → выберите бота → задайте имя/описание/иконку → укажите HTTPS-URL приложения;
     запуск: `https://t.me/<bot>/<appname>`;
   - либо `/mybots` → *Bot Settings* → *Menu Button* → укажите HTTPS-URL — кнопка появится в чате бота.
4. Откройте приложение **внутри Telegram** (не в браузере):
   - интерфейс сам перекрасится под светлую/тёмную тему клиента (`tg.themeParams`, событие `themeChanged`);
   - нижняя кнопка «Начать игру» — это Telegram **MainButton**, «‹» в игре/настройках — **BackButton**;
   - взятия/шах/мат дают вибро-отклик через `HapticFeedback`.

## Проверено

- меню/настройки/игра, переключение тем доски и сохранение настроек (localStorage);
- Pass & Play: ходы, взятия (+материал), отмена, переворот;
- бот Stockfish: ответ на ход, индикатор «бот думает»;
- подсветки ходов/последнего хода/шаха, превращение пешки, оверлей окончания партии;
- онлайн: создание комнаты и инвайт-ссылка, авто-вход по `start_param`/`?room=`,
  синхронизация ходов в обе стороны, блокировка доски на чужом ходе,
  оверлеи «Соперник сдался / отключился», подбор из очереди.
- турниры (95 автотестов сервера + прогон в браузере): создание/регистрация/старт,
  сетка 3/4/8/16/32 с байями и матчем за 3-е место, авто-вход в матчи по `match-start`,
  продвижение победителей, определение ТОП-3 (50/30/20), окно «Заявка на Приз»,
  админ-таблица выплат, «Выплачено» с удалением реквизитов, доступ админа только по
  подписанному `initData` (в DEV — по `?as=`).
- расписание (38 автотестов): авто-старт в назначенное время, форматы `startsAt`
  (мс / сек / `YYYY-MM-DDTHH:mm`), отказ на мусор и дату дальше года, снятие расписания,
  `schedule-missed` один раз при нехватке игроков, старт по второму опоздавшему игроку,
  сохранение `startsAt` в `DATA_FILE`, повторная доставка `match-start` вернувшемуся
  игроку (та же комната, противоположный цвет) и приём его результата;
- два параллельных матча одного игрока: результат засчитывается по `matchId`, а не
  «по той комнате, в которой оказался сокет»; чужой заявитель отклоняется;
- переподключение: место в комнате переходит на новый сокет того же игрока,
  heartbeat-репер убирает мёртвые соединения;
- мобильная вёрстка: меню 531×553 помещается без прокрутки (кнопка «Турниры» видна),
  горизонтального переполнения нет, панель «Нет связи с сервером» объясняет пустой список.
